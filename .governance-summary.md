## State Machine Specification

### Allowed Transitions (5 Total)

```
1. OPEN → IN_PROGRESS   (Start work)
2. OPEN → CANCELLED     (Cancel before work)
3. IN_PROGRESS → RESOLVED    (Complete work)
4. IN_PROGRESS → CANCELLED   (Cancel during work)
5. RESOLVED → CLOSED    (Finalize)
```

### Terminal States
- **CLOSED**: Finalized, no outbound transitions
- **CANCELLED**: Abandoned, no outbound transitions

### Forbidden Transitions
- All transitions FROM terminal states
- All transitions TO OPEN
- State skipping (OPEN → RESOLVED, OPEN → CLOSED, IN_PROGRESS → CLOSED)
- Reverting (RESOLVED → IN_PROGRESS, RESOLVED → OPEN)
- Invalid cancellation (RESOLVED → CANCELLED)

### Enforcement
- **Component**: `TicketStateMachine` (Service layer)
- **Approach**: Allowlist (explicitly define valid, reject all others)
- **Error**: HTTP 422 (Unprocessable Entity)
- **Testing**: Property-based tests with ≥100 iterations

## Seven Absolute Rules

### 1. No Secrets in Git
**Violation**: Critical  
**Enforcement**: Pre-commit scanning, `.gitignore` validation  
**Consequence**: Immediate rollback, incident review

### 2. Business Rules in Backend Only
**Violation**: Major  
**Enforcement**: Code review, architecture audits  
**Consequence**: PR rejection, refactoring required

### 3. API Contracts Documented
**Violation**: Minor  
**Enforcement**: PR checklist, design spec review  
**Consequence**: Request documentation in review

### 4. Tests Before Completion
**Violation**: Major  
**Enforcement**: PR checklist, CI/CD gates  
**Consequence**: PR rejection until tests added

### 5. Human Review of AI Code
**Violation**: Major  
**Enforcement**: Process requirement, PR checklist  
**Consequence**: PR rejection if unreviewed

### 6. AI Mistakes Documented
**Violation**: Minor (if missed)

**Violation**: Minor (if missed)

### Architectural Layers

```
┌─────────────────────────────────┐
│   Controller (REST Endpoints)   │  HTTP concerns only
└────────────┬────────────────────┘
             │
┌────────────▼────────────────────┐
│   Service (Business Logic)      │  Business rules, validation
└────────────┬────────────────────┘
             │
┌────────────▼────────────────────┐
│   Repository (Data Access)      │  JPA, queries
└────────────┬────────────────────┘
             │
┌────────────▼────────────────────┐
│   Database (PostgreSQL/H2)      │  Persistence
└─────────────────────────────────┘
```

**Rules**:
- Controllers → DTOs, no business logic
- Services → Business rules, no HTTP
- Repositories → Data access, no business logic
- Each layer depends only on layer below

### Error Handling Standards

**HTTP Status Codes**:
- **200 OK**: Successful GET/PATCH/PUT
- **201 Created**: Successful POST
- **204 No Content**: Successful DELETE
- **400 Bad Request**: Validation failure
- **401 Unauthorized**: Authentication required
- **403 Forbidden**: Authorization denied
- **404 Not Found**: Resource not found
- **409 Conflict**: Duplicate/conflict
- **422 Unprocessable Entity**: Business rule violation (state transition)
- **500 Internal Server Error**: Unexpected errors

**Standard Error Response**:
```json
{
  "status": 422,
  "message": "Cannot transition from CLOSED to IN_PROGRESS",
  "timestamp": "2026-09-23T10:00:00Z",
  "path": "/api/tickets/1/status"
}
```

**Validation Error Response**:
```json
{
  "status": 400,
  "message": "Validation failed",
  "timestamp": "2026-09-23T10:00:00Z",
  "path": "/api/tickets",
  "errors": [
    { "field": "title", "message": "must not be blank" }
  ]
}
```

### Testing Requirements

**Minimum Coverage**:
- Unit tests for all service methods
- Integration tests for all REST endpoints
- Property tests for state machine (≥100 iterations)
- Property tests for invariants (≥100 iterations)
- Repository tests for custom queries

**Property Test Format**:
```java
// Feature: feature-name, Property N: property-title
@Property(tries = 100)
void propertyTestMethod() {
    // Test implementation
}
```

**Test Organization**:
```
src/test/java/
├── unit/           # Isolated component tests
├── integration/    # Full context tests
├── property/       # Property-based tests (≥100 iterations)
└── repository/     # Database query tests
```
